# Continuous creature cognition: execution plan

The requested behavior is one continuously available cognitive system shared by
the visible beings: neural computation, reasoning, learning, body control,
research, replay, memory and browser tools exchange real observations and
results. Visual analytics must expose that computation and its limits. A label,
allocated array or increasing activity counter does not demonstrate useful
learning or downstream influence.

## Baseline and research

The starting committed source is `b291cde`. The existing ALIVE scheduler already
coordinates thirty capabilities. The macro/meso/micro hierarchy, compact brain
adapters, seven precision families, coupling and specialist fusion already run
on the live controller path. Review is therefore organized around missing
connections and evidence, with donor architecture fidelity kept separate.

Preexisting local trainer-state work is preserved. Its exact worker component
and tests are separate from this change; full learned-state persistence remains
a larger project. Existing production tests and reference reports are reused
where they test the relevant behavior.

Primary-source research, mechanism limitations and source findings are recorded
in `ALIVE_CONTINUOUS_RESEARCH_2026-11-09.md`. RIM/LTC/SSM, continual replay,
statistical evaluation, FlyWire and Grover sources inform the implementation;
their published results are not attributed to this browser.

## Implementation

1. Complete scheduler coverage: explicit memory and metacognitive observations,
   idempotent acknowledged DOM warp, canonical aliases, Ghost Swarm, Ghost
   Write and a distinct five-training-seed diagnostic. Preserve coalescing,
   serialized conflicting mutations, cancellation, bounded retries and Pause.
2. Make Ghost faculties part of the shared creature controller. Accepted page
   observations feed bounded provenance memory. Three research roles inspect
   those observations and produce queries/candidates; optional configured local
   inference supplies labeled proposals. The shared navigation frontier consumes
   their output. Ghost Write compiles a source-linked evidence notebook used by
   working/semantic memory. These are recurring faculties, not repeated tab
   creation or arbitrary text insertion into websites.
3. Route the legacy controls through the same jobs, eliminating duplicate
   unfenced Ghost workflows. DOM warp uses an idempotent desired state and
   acknowledged current-document effects. Only confirmed mutations get credit.
4. Add a visual brain-evidence workspace. Show actual task outcomes, source
   receipts, drafts, dependency failures, scheduler timeline, neural tensor
   statistics, learning measurements and scientific gate status. Expensive
   inspections run only while the panel is visible. No synthetic progress,
   invented model identity, or activity-derived intelligence percentage.
5. Run five independently initialized local policy trials against each trial's
   frozen baseline with fixed holdout and retained-task trajectories. Report raw
   results, parameter changes, rejected candidates and uncertainty. Keep this
   isolated from the live policy and the unqualified PDF acceptance gates.

## Verification and publication

- Test productive and unavailable paths, cancellation, deduplication, bounded
  memory, source copying, proposal consumption, draft persistence, and stale
  result rejection. Use production functions with controlled dependencies.
- Check all fourteen brain adapters and precision contributions with existing
  causal coupling tests, and inspect actual full-array statistics separately
  from downstream influence evidence.
- Run the complete Node suite and required Python/Node/Electron smoke. Run an
  isolated Electron probe covering actual script startup, the new faculties,
  visual evidence, cadence and Pause settlement, with its conditions stated.
- Write a report of changes, measured outcomes, failures and next experiments.
  Commit the completed task files and push to the configured GitHub remote;
  preserve unrelated work and local profiles/credentials/captures.

## Acceptance boundary

All registered faculties remain enabled and coordinated while the application
is running; expensive work has separate cadences and explicit prerequisites.
This does not assert parallel execution of every instruction, full execution of
every donor architecture, independent brains for every projected body, biological
FlyWire equivalence, external Eshkol or quantum hardware, consciousness, or
foundation-model weight training. Every such extension needs its own implementation
and independent evidence. G1–G8 retain their original qualification requirements.
