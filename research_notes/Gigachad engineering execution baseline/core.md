**Chronology:** the three research questions below describe the inspected starting state. The implementation update at the end supersedes the listed privacy, IPC, shutdown, smoke-isolation and PII-match-cap findings. Outstanding gaps remain explicitly listed there.

## 1. What executable baseline and isolation have actually been established?

### Takeaway

Browser-data and configuration smoke tests pass. The Electron smoke already isolates browser storage in a unique temporary directory, but the full smoke suite has not been executed in this research phase: configuration/environment/provider isolation is incomplete. Coverage is explicitly partial for the very large main process, sidecar analyzers and renderer; the exact coverage and SHA-256 evidence is [core-coverage.json](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/research_notes/Gigachad engineering execution baseline/core-coverage.json>). The pre-existing main-process diff is preserved in [core-main-before.patch](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/research_notes/Gigachad engineering execution baseline/core-main-before.patch>).

### Cited Findings

- `main.js` creates a unique temporary directory in SMOKE mode and sets `userData`, `downloads` and `sessionData` before app readiness. It disables acceleration and skips sidecar/LLM autostart. Thus the recently added persistent-genome smoke operations are temp-profile scoped. This follows Electron's requirement to override session storage before ready. [Main process](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:43>), [Electron app paths](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path).
- It nevertheless calls `loadConfig({root: ROOT})`, which reads repository `config.json`, repository `.env`, parent `.env`, inherits process secrets, and probes installed binaries. `config-save` writes repository configuration even under SMOKE. Renderer boot always refreshes model inventory and starts autonomous routines, so temporary browser storage alone does not establish a provider-free test. [Config load](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/config.js:215>), [Main config handler](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:1047>), [Renderer boot](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/index.html:24843>).
- Full smoke executes Python byte-compilation and `/tts`; the latter can invoke installed Kokoro and lazy model initialization. Its fixed default port is 8766. It strips embedding and NER model environment values, but that does not isolate every optional provider. `smoke.js` inherits `ELECTRON_RUN_AS_NODE`, while the separate Electron launcher deletes it. [Suite](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/scripts/smoke.js>), [Sidecar smoke](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/scripts/smoke_sidecar.py:137>), [Electron smoke](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/scripts/smoke_electron.js>).
- Commands actually executed: `node scripts/smoke_browser.js` → `browser data smoke passed`; `node scripts/smoke_config.js` → `config and blocklist smoke passed`. The latter creates its own temporary test roots. `py -0p` established Python 3.12 and 3.14 installations while the unqualified `python` resolves to 3.9; targeted HTTP probes therefore explicitly used `py -3.12`. No live profile, API key or user configuration content was read by these tests. [Browser smoke](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/scripts/smoke_browser.js>), [Config smoke](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/scripts/smoke_config.js>).

### Inferences

The first complete smoke should use a test-mode config factory that reads neither disk config nor dotenv nor inherited provider settings, returns inert loopback endpoints, disables autostart, rejects or temp-scopes config writes, and prevents autonomous smoke requests from invoking real providers. The sidecar test should bind port zero, run under the detected supported Python, and force deterministic standard-library-only backends including TTS. Blocking non-loopback network traffic in smoke provides a second boundary. Keep Python bytecode in a temporary cache or compile in memory. Capture real Electron boot separately from purely Node/Python checks.

### Gaps

No full desktop smoke, real local model call, cloud call, Windows installer, signed package, clean-machine test or complete renderer review has occurred in this phase. The successful unit smokes do not imply those behaviors work. Broad mathematical/audit checks belong to another team member.

## 2. Which current security and lifecycle defects warrant the first implementation units?

### Takeaway

The clearest current defect is fail-open cloud PII handling, including omitted history and image policy. A bounded code probe reproduced the failure without network access. IPC frame validation and sidecar connection bounds also require correction. Existing guest node isolation and negative-body-length checks are present; historical absence must not be reported as current.

### Cited Findings

- **P1: enabled PII firewall does not prevent unredacted outbound data.** Only the current assembled text in `ultra` mode is sent to `/ner_pii`; timeout/non-OK errors are ignored. Prior messages are appended later without redaction. Screenshots are appended later without an explicit unredacted-image policy. A remote URL configured as the local endpoint bypasses the mode-based check. The source-derived probe reports the same raw `fixture@example.test` after both a simulated timeout and HTTP failure. [Outbound path](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:2737>), [Actual request body](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:2793>), [Reproducer](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/research_notes/Gigachad engineering execution baseline/core-js-probe.js>).
- **P1/P2 defense gap: privileged IPC validates WebContents identity only.** `fromChrome()` does not require the trusted main frame or trusted document. The pure guard probe accepts a foreign subframe sharing the host WebContents. This is a guard-level demonstration, not proof that an untrusted live frame can currently access the preload bridge. Electron specifically requires accounting for frame senders, including child frames. Guest attachment does strip preloads, disables all Node integration, and enables sandbox/context isolation. [Guard](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:204>), [Guest hardening](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:471>), [Electron security](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages).
- **P2: bounded size does not mean bounded waiting.** Oversized requests synchronously drain up to 32 MB before sending HTTP 413; no read deadline is set. An isolated OS-assigned-port server using the real handler did not answer an oversized declaration with no payload within 0.515 seconds. This only proves delay at that threshold; source inspection shows no explicit eventual deadline. The same isolated server accepted `Origin: https://fixture.example.test` with `Content-Type: text/plain` JSON and returned 200. Browser network policy can limit attack reachability, which has not been established. Negative Content-Length is already rejected. [Handler](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/laya_sidecar.py:1393>), [Reproducer](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/research_notes/Gigachad engineering execution baseline/core-sidecar-probe.py>), [Python HTTP limitations](https://docs.python.org/3/library/http.server.html), [Python socketserver](https://docs.python.org/3.12/library/socketserver.html).
- **P1/P2 lifecycle defect:** `_localBrainsHttpServer` is block-scoped inside `registerIpc()` but read by the top-level `will-quit` callback, before sidecar and llama cleanup. Static lexical scope predicts a ReferenceError that can skip those cleanups. Runtime reproduction remains part of the implementation unit. [Declaration](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:1959>), [Quit callback](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:3248>).
- Configuration defaults and fallback routing still contain particular model identifiers and claims of model speed. Explicit local model preferences and fallback to models not present in the inventory violate portable discovery expectations. Configuration save cannot clear several credential/path strings with an empty value, and JSON persistence silently swallows file failures in general stores. These are subsequent reliability work, not proven failures of the current targeted smoke. [Defaults](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/config.js:5>), [Save semantics](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/config.js:302>), [Fallback](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:2828>).

### Inferences

Implement a pure outbound policy at the final request boundary: classify destination rather than UI mode, sanitize every text message, fail closed on unavailable/malformed sanitizer responses, and require explicit consent for unredacted images. Protect each retry through the same policy and reject redirects to avoid local-to-remote policy bypass. Keep error codes actionable and preserve cloud vision behind an explicit consent route. Then strengthen IPC authorization to exact live top-frame/document and validate it with negative cases. Correct the shutdown scope and verify callback cleanup. Follow with sidecar timeouts, input-media-type/origin perimeter, bounded concurrency and owned-process readiness.

OWASP REST guidance supports validating request content types and rejecting unsupported representations; use a service-specific threat model rather than claiming broad OWASP compliance. [OWASP REST security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html).

### Gaps

No external exploit was attempted. No claim of remote code execution is established. Preload channel coverage, privileged argument validation, prompt-injection action authorization, full persistence/corruption recovery and browser-wide permission flows remain incompletely reviewed. Optional model load statuses and the rest of sidecar analyzers need deeper qualification.

## 3. What should the next Windows implementation and release gates be?

### Takeaway

The repository currently has development start and smoke paths, not a demonstrated Windows distribution pipeline. First secure and isolate a reproducible desktop test, then make packaging an independently verifiable deliverable.

### Cited Findings

- Package metadata pins Electron 42.11.18, Node >=20 and `npm start` → `electron .`; there is no package/make/distribute script or installer tool in the manifest reviewed. Python 3.11+ is an external runtime requirement. [Package](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/package.json>), [AGENTS](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/AGENTS.md>).
- CI now runs `npm ci` (the old missing-install issue is superseded) on Windows/Ubuntu, but sets `GIGACHAD_SKIP_ELECTRON=1`. Its success therefore does not establish desktop boot, guest preload isolation, artifact installation or uninstall. [CI](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/.github/workflows/ci.yml>).
- Windows-native child spawning uses `windowsHide` in inspected sidecar/llama paths. Main `ensureLlama()` attaches exit handling but no error listener to the spawned child; failed execution can become an unhandled process error. [Child lifecycle](<Z:/[Vibe Coded (AI)]/CLAUDECODE/gigachad-browser/main.js:335>).

### Inferences

Sequence the next units: (1) outbound privacy plus frame authorization and shutdown cleanup; (2) safe smoke configuration and standard-library sidecar fixtures; (3) actual isolated Electron boot with logs and stable assertions rather than self-scored audit numbers; (4) Windows packaging definition, sidecar runtime policy, data/config location migration, clean-machine install/uninstall, update recovery and signing prerequisites; (5) model-selection portability, atomic persistence and clear credential lifecycle. Each unit needs command results and a narrow acceptance matrix before proceeding.
